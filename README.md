# Creator scraping evidence dashboard

An unofficial research appendix for a Blibli affiliate case study. The static dashboard supports cohort filters, theme drill-down, searchable saved records, source inspection and screenshot mode.

## Evidence scope

The 3 October 2026 snapshot contains 119 unique discovery posts and 183 unique TikTok comments. The core qualitative analysis uses 28 evidence rows from 26 sampled platform accounts across 10 discussion clusters. Accounts with fewer than 1,000 followers are separated from those with 1,000–9,999.

These are purposively selected public discussions, not survey respondents or a representative population. Account counts are not verified unique-person counts. The study does not establish category superiority, residence or city tiers, causal platform failures, willingness to switch, or current independent firsthand Blibli experience.

E42 is retained as a context summary without a saved verbatim subtitle transcript. It is not presented as a direct quote. Four supplemental curated observations remain outside the core counts.

## Files

- `index.html`: self-contained dashboard; no install or API credentials required.
- [Blibli_Creator_Raw_Data.xlsx](Blibli_Creator_Raw_Data.xlsx): selected fields from saved Apify extracts. The publication copy redacts incidental contact details from public bios; the original local raw workbook is retained separately.
- [Blibli_Creator_Needs_Research.xlsx](Blibli_Creator_Needs_Research.xlsx): coded evidence, findings, method and spending ledger.
- `.nojekyll`: serves the dashboard as static files on GitHub Pages.

Open `index.html` locally, or use GitHub Pages with the repository's main branch and root folder. The dashboard loads its saved snapshot from the HTML file; it does not perform new scraping or refresh data automatically.

Source links and record locators support verification. Public source content remains attributable to its respective authors. This project is not an official Blibli product or dashboard.

## Reviewing or handing off a finding

1. Locate the saved record and its source link in the dashboard.
2. Compare the claim with the coded evidence and method in the research workbook; use the raw-data publication copy for the selected saved fields.
3. Keep the snapshot date, sampling limits and distinction between core and supplemental evidence alongside the finding.
4. Treat E42 as contextual summary rather than a verbatim transcript.

A source link identifies where evidence originated; it does not establish that the live page still matches the saved snapshot. Record a new access date and any differences when rechecking a source. New observations should be identified separately from the frozen core counts.
